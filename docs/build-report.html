Findings, ranked by consequence

What turned up

01

The dataset is not aerial

LibreYOLO/weed-crop-aerial sounds like drone imagery. It isn't. “Aerial” is a Roboflow-100 domain-category label, not a description of the photographs.

They are close-range ground-level shots, roughly 30–80 cm above the soil — individual seedlings filling much of the frame.

Caught by opening the annotated predictions, not by reading a metric. Every aggregate number looked perfectly healthy.

02

The crop class was trained indoors, on plastic seed trays

Following finding 01 further: splitting the dataset by filename and counting labels shows it is three different visual domains, not one.

Sub-populationImagescropweed
3xxxx_ — outdoor, soil close-up88375,926
IMG_* — indoor propagation trays2414031,401
other — mixed ground-level520115

98.3% of every crop label is in the indoor tray images — visibly plastic seed trays, electrical cables, a plastic floor grate.

So the file contains two models: a weed detector trained outdoors, and a crop detector trained indoors. The crop AP of 0.363 is real, and it measures seedlings in trays. It says nothing about finding a crop in a field.

What to do with this

Use the weed class. Treat crop as unvalidated for any outdoor use until it is retrained on real field imagery.

03

Weed detection from survey altitude is an optics problem

Letterboxing a 4056-wide camera frame down to the 640×640 network input discards 6.3× of linear resolution before inference happens. For small targets that is the whole game.

Maximum altitude at which the target still spans ~20 px. Pi Camera Module 3. Bars share one scale, 0–130 m.

At a normal 30 m survey altitude a 3 cm seedling is 2.6 px natively and 0.4 px after downscaling. No amount of training recovers that.

The decision this forces

Seedling-stage spot-spraying and patch-level mapping are different products, with different airframes and flight profiles. Pick one before buying hardware.

04

Tiling recovers most of it — built and measured

Slicing frames into native-resolution tiles instead of downscaling buys back the full 6.3×. Measured on a 1280×1280 mosaic of real test imagery:

MethodDetections
Whole-frame (2× downscale)29
Tiled66
Per-image native (reference)61

2.3× more detections, matching the native reference. Costs one inference per tile — a full 4056×3040 frame is ~56 tiles, far too slow on the Pi CPU. That is an argument for the Hailo NPU.

05

Class balance is 95% weed / 5% crop

The opposite of what I assumed when planning — only 278 crop boxes in training. A model that predicts only weed still posts a respectable aggregate mAP, so the evaluator leads with per-class AP.

I initially called crop “effectively untrainable.” By epoch 10 it reached AP 24.2 on validation, so that call was too pessimistic — the final test-split numbers get to settle it, not my earlier framing.

06

Your GPU is power-capped

SW Power Cap: Active — 217 MHz of 3090 MHz, P-state P4, on AC at 65 °C, so not thermal. Throttled: 5.8 s/iter. Unthrottled: 0.32 s/iter — an 18× difference.

I deliberately left your power settings alone while you were asleep. Windows power mode → Best performance, Acer NitroSense → Performance, NVIDIA Control Panel → Prefer maximum performance.

Verification

How the pipeline was checked

Not “it ran without error” — each of these is an independent check against something that could disagree.

  • Decoder vs upstream. The numpy YOLOX decode matches YOLOX's own torch implementation to 1e-5 on random input, square and non-square.
  • Known-answer image. The COCO model on dog.jpg returns bicycle 0.96 / dog 0.90 / truck 0.54 with pixel-tight boxes on a non-square frame — so the whole geometry path is right.
  • Every annotation re-derived. All 7,852 boxes recomputed from their source labels through pycocotools. All round-trip.
  • Full stack. Integration tests drive the real ONNX model through the real pipeline, asserting provenance, geometry, spool priority and the safety gate.

The thing that still isn't done

All of the above is scaffolding. The model that matters is the one fine-tuned on imagery from the fields you actually intend to fly, at the altitude you intend to fly.

That is also the only point at which validated_locally may become true — the flag separating a scouting aid from something allowed to influence chemical application. It is enforced in code, all the way from the model file to every spooled frame.
