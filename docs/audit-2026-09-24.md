# Verification audit and platform roadmap — 24 September 2026

Second audit of `Anwarito-lbd/agri-edge` and `Anwarito-lbd/agri-edge-web`,
following [audit-2026-09-19.md](audit-2026-09-19.md). That audit asked whether
the checks were running. This one asks two questions: **would it work on the
first real field day**, and **what does it take to be a full smart-farm
platform** rather than a scouting demo.

Findings F1–F15 came from reading the code against its own contracts and were
each reproduced by a failing test before being fixed. W1–W5 are in
`agri-edge-web` and are **not fixed here** (separate repo).

---

## Verdict

**The architecture and the safety discipline are sound.**
- Rule 1 still holds by absence: no code path in `src/` can drive a motor, pump or valve.
- MAVLink stays read-only, and a test enforces it.
- Treatment fails closed.
- Licence hygiene is good.
- `docs/status.md` is honest about hardware.

**The weak point is the space between modules.** Most "done" pieces are islands:
- The detection API, vehicle adapter, model registry, MQTT bridge, NTRIP, coverage planner and calibration are imported only by tests.
- The ops backend runs on `seed_demo()` data held in memory.
- Nothing is published from the edge.
- Irrigation and weather logic are thresholds, not agronomy.

There is no end-to-end flow yet: **field → edge → store → decision → farmer**.

## Findings — agri-edge-web (fixed in Anwarito-lbd/agri-edge-web#3)

| # | Defect | Fix |
|---|---|---|
| W1 | No auth, no CSP or security headers. With `OPS_ALLOW_WRITES=1` the proxy accepted a `text/plain` cross-site POST (CSRF) and forwarded it as JSON | Logins with an httpOnly SameSite=Strict cookie forwarded as a bearer token; writes must be `application/json` (415) and same-origin (403); CSP and security headers in `next.config.ts` |
| W2 | The write allowlist included `seed` (wipes the store) and `detections`, lacked resolve/escalate/etc., and was never checked against the backend | `seed`, `detections`, `ingest`, `auth/users` removed; real routes added; a contract test pins the list to the ops API's POST routes |
| W3 | ACK returned 403 by default (undocumented); `GET /audit` exposed; the vehicle block list matched prefixes only | With a session, roles are enforced upstream; audit is admin/auditor only; a vehicle word in any path segment is refused |
| W4 | MultiPolygons never drawn; mobile nav hid Companion/Ops; SSE ran `tickMock` once per viewer | MultiPolygons drawn; mobile nav shows every item; the demo clock ticks once per interval however many viewers |
| W5 | Over-claims: "88/88 sim-complete", "Software ready", "SSE live" on mock data | Replaced with what is true |

Found by the end-to-end run against the real ops API, and fixed with tests:

- **Every login refused off localhost.** The same-origin check compared `Origin` with `request.url`, which `next start` builds from its bind address. It now compares with `Host` / `X-Forwarded-Host`.
- **Open redirect after login.** `next=/\evil.example` passed a leading-slash check (browsers read `/\` as `//`). The value is now resolved as a URL and kept only if it stays same-origin.

## Roadmap to a full smart-farm platform

Ordered by value per unit of effort. Each item plugs into the existing
adapter pattern. None of them changes the four safety rules.

### Improve — make what exists real

1. **Close the loop edge → store.**
   - An MQTT publisher on the edge: detections as GeoJSON, health, frame summaries.
   - Wire `MqttBridge` into the ops store (paho-mqtt as an extra).
   - HTTP ingestion routes for readings.
   - Persistence the API actually uses.
   - Merge or remove the duplicate `detection/` API.
2. **Time integrity.**
   - Use the autopilot's `time_boot_ms` / `TIMESYNC` and Picamera2's `SensorTimestamp`.
   - Interpolate the pose at exposure time.
   - Record telemetry age in each sidecar.
3. **Georeference hardening.**
   - Checkerboard intrinsics and distortion.
   - Rangefinder AGL, or a DEM (Canadian HRDEM/CDEM) otherwise.
   - A total error budget, not terrain only.
4. **Cross-frame dedup.** Cluster detections within their error radius, so one weed seen in five frames counts once. This produces **weed density maps**.
5. **Camera control.**
   - Manual shutter from `training/motion_budget.py`.
   - JPEG/PNG plus a thumbnail instead of 36 MB `.npy` files.
6. **Edge operations.**
   - systemd unit + watchdog, SIGTERM handling, log rotation.
   - Armed/flying-aware capture, health telemetry.
   - Signed OTA of models.
   - sha256 check of models at load.
7. **Training reproducibility.**
   - Pin HF dataset revisions and seeds.
   - Fill the registry's null hashes and use relative paths.
   - Finish the model cards.
8. **CI.**
   - Container build (A4 remainder).
   - Backend↔proxy contract test.
   - `npm audit`, and actions pinned to a SHA.

### Add — what makes it a platform

**Status (24 Sept, later):** items 2–7 below and item 1 of "Improve" are
built in software with tests. The modules are `satellite/`, `agronomy/`,
`prescription/`, `iot/provision.py` + `iot/lorawan.py` + `ground_iot/`,
`learning/`, `ops/auth.py`, and the web app in agri-edge-web. None has run
on hardware or live services. Item 1 (farm model) exists as field profiles,
without two-way farmOS sync. Item 8 exists as explained recommendations.

1. **Farm data model as system of record.**
   - Farm → field (drawn boundary) → zone → crop season (crop, variety, seeding date, stage).
   - Two-way farmOS sync of assets, logs and quantities.
2. **Satellite baseline — the cheapest big win, no hardware.**
   - Sentinel-2 L2A NDVI/NDRE per field: 10 m, ~5-day revisit, free via Copernicus / Element84 STAC.
   - Cloud masking from the SCL band, and anomaly detection against field history.
   - The drone becomes a **targeted scout** sent where the satellite flags a change.
3. **Agronomy engine** (numpy-only, fits the Pi boundary):
   - Weather adapter: ECCC / Open-Meteo forecast and observations.
   - FAO-56 Penman-Monteith ET0 → Kc by growth stage → per-zone soil-water balance. This replaces the `<20% → 10 mm` rule.
   - Seasonal GDD → BBCH stage estimate.
   - Disease-risk windows: sclerotinia (canola), fusarium head blight (wheat), late blight (potato).
   - Explicit frost-protection policy.
4. **Prescriptions to real machines.**
   - Weed-density and vigour zones → ISOXML (ISO 11783-10) and shapefile for existing sprayers.
   - This delivers ROI without drone spraying, behind the existing fail-closed approval.
5. **Ground IoT for real.**
   - ESP32 firmware (ESPHome / PlatformIO) for soil moisture/temperature and a weather station.
   - LoRaWAN via ChirpStack for range.
   - TLS + per-device credentials.
   - Device registry with last-seen and battery.
6. **Learning loop** — the only road to `validated_locally: true`.
   - Spool → Label Studio / CVAT.
   - Active learning: low confidence and disagreement first.
   - Per-farm validation report → retrain → hashed registry → OTA.
7. **Farmer app.**
   - Real users and roles, so the audit log names a person.
   - PWA with offline tiles.
   - French (Canadian market).
   - Field drawing; detection, density and NDVI layers with a timeline.
   - Push/SMS alerts; scouting tasks.
8. **Decision layer.**
   - Fuse satellite + drone + IoT + weather + agronomy into ranked, *explained* recommendations. For example: "scout zone B — NDVI −18% vs 14-day trend, sclerotinia risk high".
   - A human approves every action.
   - Any LLM assistant is advisory and read-only.
